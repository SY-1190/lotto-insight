# Lotto Insight

한국 로또 6/45의 **1회부터 최근 추첨 회차까지** 당첨번호를 분석하는 단일 HTML 웹앱입니다. 디자인, CSS, JavaScript, 수집한 전체 이력이 `index.html` 하나에 들어 있습니다. 별도 서버나 API 키, 빌드 도구 없이 실행됩니다.

[공개 웹앱](https://sy-1190.github.io/lotto-insight/) · [GitHub 저장소](https://github.com/SY-1190/lotto-insight)

## 사용하기

`index.html`을 내려받아 브라우저에서 열거나, 저장소의 GitHub Pages 공개 주소로 접속합니다. 처음 실행할 때 내장 이력으로 분석하므로 외부 폰트나 라이브러리를 내려받을 필요가 없습니다.

- **기간:** 최근 20회·50회·100회·전체에서 선택합니다. 기본은 최근 100회입니다.
- **HOT / COLD:** 상위·하위 9개 번호를 같은 눈금의 가로 막대그래프로 비교합니다.
- **전체 번호 분포:** 1~45번의 출현 횟수를 세로 막대그래프로 확인하고, 막대를 누르면 출현 비율과 마지막 출현 회차를 볼 수 있습니다. 모바일에서는 좌우로 스크롤할 수 있습니다.
- **5게임 추천:** 주사위 버튼을 누를 때마다 새 조합을 생성하며 각 번호에 HOT·COLD·보통 상태를 표시합니다.
- **전체 이력:** 회차 검색과 페이지 이동으로 과거 당첨번호 및 보너스를 조회합니다.
- **최신 상태:** 수집된 마지막 회차와 날짜를 표시하고, 다음 회차 발표 시점 이후에도 데이터가 갱신되지 않았다면 최신 확인이 필요함을 안내합니다.

로컬에 내려받은 HTML에는 저장 시점의 전체 이력이 내장되어 있습니다. **최신 데이터 확인** 버튼은 공개 미러 두 곳의 전체 이력을 대조하고, 기존 기록과 충돌하지 않을 때만 현재 화면에 새 회차를 반영합니다. 이 작업은 내려받은 HTML 원본을 변경하지 않습니다. 공개 페이지의 내장 데이터는 아래 GitHub Actions로 갱신합니다.

## HOT·COLD의 의미

보너스 번호를 제외한 **6개 본번호**의 출현 횟수를 계산합니다. 빈도가 높은 순으로 정렬하되, 동률이면 마지막 출현 회차가 더 최근인 번호, 그다음 번호가 작은 순서로 정렬합니다.

| 분류 | 기준 |
| --- | --- |
| HOT | 정렬된 45개 번호의 상위 9개 |
| COLD | 같은 정렬의 하위 9개 |
| 보통 | 나머지 27개 |

분류는 선택한 분석 기간에 상대적인 값입니다. 번호가 충분히 자주 나왔는지에 대한 통계적 유의성 판단이나 다음 회차의 예측을 뜻하지 않습니다.

### 추천 구성

| 게임 | 구성 |
| --- | --- |
| 균형 | HOT 2 + COLD 2 + 보통 2 |
| HOT 중심 | HOT 4 + COLD 1 + 보통 1 |
| COLD 중심 | HOT 1 + COLD 4 + 보통 1 |
| HOT + 보통 | HOT 3 + 보통 3 |
| 전체 무작위 | 1~45 전체에서 6개 |

각 게임 안에서 번호를 중복 선택하지 않고, 한 번에 생성한 5게임도 같은 조합이 되지 않도록 처리합니다. 분석 기간을 변경하면 해당 분류에 맞춰 조합을 다시 생성합니다.

**과거 빈도는 다음 추첨의 당첨 확률을 높이지 않습니다.** 공정하고 독립적인 6/45 추첨에서 어느 6개 조합이든 1등 확률은 `1 / 8,145,060`으로 같습니다. 추천은 통계 탐색과 조합 생성용입니다.

## 데이터 출처와 검증

우선 출처는 [동행복권 공식 당첨결과](https://www.dhlottery.co.kr/lt645/result)입니다. 갱신 스크립트는 공식 전체 회차 JSON의 회차·추첨일·6개 본번호·보너스만 추출합니다.

공식 서버를 이용할 수 없을 때는 다음 두 공개 미러의 **전체 회차 데이터가 모두 일치할 때만** 사용합니다.

- [smok95/lotto 전체 이력](https://smok95.github.io/lotto/results/all.json)
- [papaya5rhw1984/lotto-data 전체 이력](https://papaya5rhw1984.github.io/lotto-data/all.json)

공식 조회 주소:

```text
https://www.dhlottery.co.kr/lt645/selectPstLt645Info.do?srchStrLtEpsd=1&srchEndLtEpsd={최근회차}
```

갱신 때 다음 조건을 검사합니다.

1. 1회부터 최근 예상 추첨 회차까지 누락·중복 없이 이어져야 합니다.
2. 추첨일은 1회 `2002-12-07`을 기준으로 매주 토요일과 정확히 일치해야 합니다.
3. 본번호 6개와 보너스는 1~45의 정수이고, 7개 숫자 안에 중복이 없어야 합니다.
4. 한국 시각 토요일 20:45를 기준으로 아직 추첨하지 않은 미래 회차는 거부합니다.
5. 기존 HTML에 들어 있는 과거 회차와 새로운 데이터가 충돌하면 자동 수정하지 않습니다.
6. 네트워크 오류, 조회 형식 변경, 미러 간 불일치, 최신 회차 미발표 등이 발생하면 **기존 HTML을 그대로 보존**하고 실패 상태로 종료합니다.

20:45는 최신 회차가 나왔어야 하는 시점을 계산하는 경계입니다. 발표 지연 시 존재하지 않는 결과를 만들지 않으며, 후속 일정에서 다시 조회합니다. 실제 당첨 여부는 동행복권에서 최종 확인하세요.

## 자동 갱신과 공개 배포

`.github/workflows/update-lotto.yml`은 다음 한국 시각에 실행하도록 설정되어 있습니다.

| 한국 시각 | GitHub Actions의 UTC 설정 |
| --- | --- |
| 토요일 21:15, 22:15 | 토요일 12:15, 13:15 |
| 일요일 09:15 | 일요일 00:15 |

GitHub의 예약 실행은 지연될 수 있습니다. `Actions → Update Lotto and Deploy Pages → Run workflow`로 수동 실행할 수도 있습니다.

갱신 → 무결성 검사 → 변경된 HTML 커밋 → Pages 배포를 하나의 워크플로에서 처리합니다. `GITHUB_TOKEN`으로 만든 커밋이 다른 워크플로를 다시 실행하지 않는 경우에도, 같은 실행에서 배포까지 완료합니다. 공개 웹사이트 산출물에는 **index.html 하나만** 포함합니다.

### 새 저장소에서 설정할 때

1. 이 파일들을 공개 GitHub 저장소의 `main` 브랜치에 저장합니다.
2. 저장소 `Settings → Pages → Build and deployment → Source`를 **GitHub Actions**로 선택합니다.
3. `Actions` 탭에서 **Update Lotto and Deploy Pages**를 한 번 실행합니다.
4. 성공한 `deploy` 작업의 공개 URL을 엽니다.

워크플로는 데이터 커밋 작업에 `contents: write`, 배포 작업에 `pages: write`와 `id-token: write`만 부여합니다. 저장소 정책에서 Actions 쓰기 또는 Pages 배포가 제한되어 있으면 소유자가 해당 정책을 조정해야 합니다.

## 로컬 갱신 / 검증

Python 3.11 이상만 필요하며 추가 패키지를 설치하지 않습니다.

```bash
# 공개 원천을 조회하여 내장 데이터를 갱신
python scripts/update_lotto.py --file index.html

# 네트워크나 쓰기 없이 내장 데이터만 검사
python scripts/update_lotto.py --file index.html --check-only

# 특정 한국 날짜 기준으로 재현 검사
python scripts/update_lotto.py --file index.html --check-only --as-of 2026-10-21

# 데이터 오류·원본 보존·시간 경계·JSON 삽입 안전성 테스트
python -m unittest discover -s tests -v
```

수집이 성공하면 기존 HTML의 `id="lotto-data"`인 JSON 영역만 교체합니다. 디자인이나 기능 코드는 변경하지 않습니다. 임시 파일을 같은 폴더에 완전히 쓰고 교체하므로 중간 저장으로 HTML이 잘리는 일을 피합니다.
